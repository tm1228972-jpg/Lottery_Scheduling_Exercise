# راهنمای فنی تمرین ۱ — زمان‌بندی لاتاری

## ۱. معرفی دقیق مسئله

در هر تصمیم زمان‌بندی، اگر چند پردازه آماده باشند باید یک پردازه برای اجرای نوبت بعد انتخاب شود. Lottery Scheduling یک سازوکار سهم‌بندی احتمالاتی است: به هر پردازهٔ آماده تعدادی بلیت صحیح و مثبت اختصاص داده می‌شود و انتخاب یکنواخت یک بلیت، برنده را تعیین می‌کند. برای پردازهٔ `i` با `tᵢ` بلیت از مجموع `T`، احتمال برنده‌شدن در یک قرعه‌کشی `tᵢ/T` است.

این مدل آموزشی از مفاهیم «قرعه‌کشی مستقل» و «مجموعهٔ آمادهٔ ثابت در هر trace» استفاده می‌کند. به‌روزرسانی وضعیت پردازه در پاسخ به اجرای واقعی CPU پیاده‌سازی نشده است.

## ۲. مراحل علمی الگوریتم

1. مجموعهٔ غیرتهی از پردازه‌های آماده دریافت می‌شود.
2. هر پردازه باید نام غیرتهی و تعداد صحیح و مثبت بلیت داشته باشد؛ نام‌های تکراری رد می‌شوند.
3. مجموع بلیت‌ها `T` محاسبه می‌شود.
4. مولد شبه‌تصادفی یک عدد صحیح یکنواخت `k` در بازهٔ بستهٔ `1..T` تولید می‌کند.
5. بلیت‌ها به ترتیب پردازه‌ها در بازه‌های تجمعی و بدون هم‌پوشانی قرار می‌گیرند. اولین بازه‌ای که انتهای تجمعی آن حداقل `k` باشد، پردازهٔ برنده را مشخص می‌کند.
6. شیء `Draw` شامل شمارهٔ بلیت، مجموع بلیت‌ها و پردازهٔ برنده برگردانده می‌شود.
7. برای trace چندمرحله‌ای، همین فرایند به تعداد درخواست‌شده تکرار می‌شود.

### شبه‌کد

```text
LOTTERY(ready):
    require ready is non-empty
    T ← sum(process.tickets for process in ready)
    k ← uniform_integer(1, T)
    cumulative ← 0
    for process in ready:
        cumulative ← cumulative + process.tickets
        if k ≤ cumulative:
            return (k, process)
```

### بازه‌های نمونه

برای `P1:1`، `P2:2` و `P3:4`، مجموع `T=7` است. بازه‌های شمارهٔ بلیت به‌ترتیب `P1:[1,1]`، `P2:[2,3]` و `P3:[4,7]` هستند. این نگاشت قطعی است؛ تصادفی‌بودن فقط در انتخاب `k` قرار دارد.

## ۳. اجزای پیاده‌سازی

- `Process`: رکورد تغییرناپذیر شامل `name` و `tickets`؛ مقادیر نامعتبر هنگام ساخت رد می‌شوند.
- `LotteryScheduler`: مجموعهٔ پردازه‌ها، مجموع بلیت‌ها و `random.Random(seed)` را نگه می‌دارد.
- `draw()`: یک قرعه‌کشی انجام می‌دهد و برای بازرسی، شمارهٔ بلیت برنده را نیز ثبت می‌کند.
- `run(draws)`: trace تغییرناپذیر می‌سازد و تعداد منفی یا غیرصحیح را رد می‌کند.
- `expected_share(name)`: نسبت نظری بلیت پردازه را می‌دهد؛ این مقدار با فراوانی محدود نمونه یکی نیست.

## ۴. سناریوی اجرا و تحلیل داده

اسکریپت مولد نمودار از خود کلاس `LotteryScheduler` با پردازه‌های `P1=1`، `P2=2` و `P3=4`، seed برابر `20261123` و ۵۰٬۰۰۰ draw استفاده می‌کند. خروجی دقیق:

| پردازه | بلیت | سهم نظری | شمار draw | سهم مشاهده‌شده |
|---|---:|---:|---:|---:|
| P1 | 1 | 14.285714٪ | 7,243 | 14.486٪ |
| P2 | 2 | 28.571429٪ | 14,420 | 28.840٪ |
| P3 | 4 | 57.142857٪ | 28,337 | 56.674٪ |
| **جمع** | **7** | **100٪** | **50,000** | **100٪** |

شمارها از فایل [`../outputs/lottery-frequency.csv`](../outputs/lottery-frequency.csv) خوانده شده‌اند و با اجرای `tools/generate_figures.py` از نو تولید می‌شوند. نزدیک‌بودن نمونه به سهم نظری با مفهوم تناسب سازگار است؛ یک seed و یک sample اثبات‌کنندهٔ کیفیت آماری، زمان اجرا یا fairness تضمینی نیستند.

## ۶. مزایا، معایب و فرض‌ها

**مزایا:** سازوکار ساده؛ بیان روشن سهم نسبی؛ امکان تغییر نسبت‌ها با تغییر ticket count؛ تکرارپذیری trace برای آزمون با seed ثابت.

**معایب/محدودیت‌ها:** برای تعداد کم drawها انحراف زیاد ممکن است؛ قرعه‌کشی به‌تنهایی موعد یا حد انتظار قطعی نمی‌دهد؛ در مدل فعلی ماندگاری پردازه‌ها ثابت است؛ زمان‌بندی، blocking، ورود/خروج، تغییر بلیت، چند‌هسته‌ای‌بودن و هزینه‌های سیستم‌عامل پوشش داده نشده‌اند.

**فرض‌ها:** هر پردازهٔ حاضر در فهرست واجد انتخاب است؛ بلیت‌ها مثبت و ثابت‌اند؛ مولد شبه‌تصادفی برای مثال کافی است؛ هر draw یک dispatch انتزاعی است.

## ۷. بازتولید و آزمون

از ریشهٔ مخزن:

```bash
python -m pip install -e .
python examples/run_lottery_demo.py
python -m unittest discover -s tests -v
python -m pip install -e ".[docs]"
python tools/generate_figures.py
```

آزمون‌های مرتبط در `tests/test_lottery.py` خطاهای ورودی، بازهٔ بلیت، برابری trace برای seedهای برابر، نسبت نظری و یک کنترل فراوانی نمونهٔ seeded را می‌پوشانند. آزمون آماری فقط sanity check با tolerance است، نه اثبات توزیع برای همهٔ اجراها.
