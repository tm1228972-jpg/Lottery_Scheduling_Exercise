# یادداشت فنی — تمرین ۱: زمان‌بندی لاتاری

**نوع سند:** یادداشت آغازین مبتنی بر کد موجود، نه گزارش نهایی چهل‌صفحه‌ای
**نسخهٔ مدل:** پیاده‌سازی آموزشی Python، seed آزمایش `20261123`

## چکیده

زمان‌بندی لاتاری یک روش سهم‌بندی احتمالاتی است. به هر پردازهٔ آماده تعداد بلیت مثبت نسبت داده می‌شود و یک بلیت به‌صورت یکنواخت از مجموعهٔ بلیت‌ها انتخاب می‌شود. در نتیجه، احتمال dispatch شدن پردازه‌ای با `tᵢ` بلیت از مجموع `T` برابر `tᵢ/T` است. این گزارش یک مدل سادهٔ قابل اجرا را تشریح می‌کند، ورودی‌های نامعتبر آن را مشخص می‌سازد و خروجی ۵۰٬۰۰۰ قرعه‌کشی seeded را با نسبت نظری مقایسه می‌کند.

## مسئله، مدل و فرض‌ها

مسئلهٔ مدل‌شده انتخاب یک برنده از میان پردازه‌های آماده است. فهرست پردازه‌ها در طول یک اجرای `run()` ثابت می‌ماند؛ drawها مستقل و مولد تصادفی شبه‌تصادفی و seeded است. هیچ زمان CPU واقعی، وقفه، context switch، blocking، ورود پردازه یا تغییر پویای بلیت شبیه‌سازی نمی‌شود. بنابراین اصطلاح «زمان‌بندی» در این سند به انتخاب dispatch انتزاعی اشاره دارد.

## قاعده و تحلیل

برای هر پردازه `i` تعداد `tᵢ > 0` بلیت در نظر گرفته می‌شود. مجموع بلیت‌ها `T = Σ tᵢ` است. یک مقدار صحیح `k` از `1..T` تولید و به بازهٔ تجمعی مالک بلیت نگاشت می‌شود. بنابراین `P(i)=tᵢ/T`. این رابطه احتمال انتخاب در یک draw است، نه تضمین سهم دقیق در یک بازهٔ محدود.

برای پردازه‌های `P1=1`، `P2=2` و `P3=4`، بازه‌ها به صورت `[1]`، `[2,3]` و `[4,7]` هستند. هر بلیت دقیقاً یک مالک دارد؛ بنابراین برای هر `k` معتبر نگاشت یکتا است.

## پیاده‌سازی و کنترل خطا

`Process` نام و تعداد بلیت را نگه می‌دارد. نام خالی، بلیت غیرصحیح/غیرمثبت و نام تکراری رد می‌شوند. `LotteryScheduler.draw()` با `random.Random(seed)` یک بلیت و مالک آن را برمی‌گرداند. `run(n)` trace کامل ایجاد می‌کند؛ `n` منفی یا غیرصحیح پذیرفته نمی‌شود. `expected_share()` نسبت نظری را از شمار بلیت محاسبه می‌کند.

## آزمایش بازتولیدپذیر و تحلیل خروجی

مولد شکل از ۵۰٬۰۰۰ draw و seed `20261123` استفاده کرد. خروجی ثبت‌شده در `outputs/lottery-frequency.csv` است:

| پردازه | بلیت | نظری | drawهای مشاهده‌شده | مشاهده‌شده |
|---|---:|---:|---:|---:|
| P1 | 1 | 14.285714٪ | 7,243 | 14.486٪ |
| P2 | 2 | 28.571429٪ | 14,420 | 28.840٪ |
| P3 | 4 | 57.142857٪ | 28,337 | 56.674٪ |

جمع drawها دقیقاً ۵۰٬۰۰۰ و سهم‌های مشاهده‌شده جمعاً ۱۰۰٪ است. فاصلهٔ مشاهده با نظری برای نمونهٔ متناهی قابل انتظار است. چون فقط یک seed بررسی شده، از این آزمایش نمی‌توان نتیجهٔ عمومی دربارهٔ کران انحراف، عملکرد یا fairness گرفت.

## شکل‌ها و شیوهٔ خواندن

1. `figures/lottery-pipeline.svg` مسیر مفهومی از ready set به pool، قرعه‌کشی و dispatch را نشان می‌دهد؛ محدودیت‌های وضعیت پردازه را عمداً خارج می‌گذارد.
2. `figures/lottery-control-flow.svg` مراحل محاسبهٔ مجموع، draw و انتخاب بازهٔ تجمعی را نمایش می‌دهد.
3. `figures/lottery-frequency.png` سهم مشاهده‌شده را به صورت میله و سهم نظری را به شکل خط نشان می‌دهد. این تصویر، خروجی دادهٔ ثبت‌شده است؛ معیار سرعت نیست.

## مزایا، معایب و کاربرد

در مدل تناسبی، تغییر تعداد بلیت‌ها نسبت احتمال را به شکلی قابل فهم تغییر می‌دهد و می‌توان سهم‌های وزن‌دار را نمایش داد. با این حال، یک قرعه‌کشی ممکن است پردازه‌ای کم‌بلیت را انتخاب کند یا پردازهٔ دیگری را در چند draw کوتاه پیاپی برنده سازد. بنابراین برای deadline، حد انتظار قطعی یا عدم گرسنگی قطعی باید سیاست‌های دیگری یا تضمین‌های اضافه طراحی شود. کاربرد این پیاده‌سازی آموزشی/تحلیلی است، نه جایگزین kernel scheduler.

## بازتولید

```bash
python -m pip install -e .
python examples/run_lottery_demo.py
python -m unittest discover -s tests -v
python -m pip install -e ".[docs]"
python tools/generate_figures.py
```

مولد شکل seed و تعداد draw را در خروجی CSV ذخیره می‌کند. آزمون‌ها در `tests/test_lottery.py` هستند.

## محدودیت گزارش و منابع

در مخزن اولیه فایل کد، گزارش یا منبع درسی وجود نداشت. این یادداشت صرفاً ادعاهای قابل پشتیبانی با مدل فعلی را بیان می‌کند؛ گزارش Word/PDF چهل‌صفحه‌ای تولید نشده تا از تکرار یا نتیجه‌سازی پرهیز شود. منبع کلاسیک پیشنهادی برای بازبینی و قالب‌بندی ارجاع طبق دستور استاد: Carl A. Waldspurger و William E. Weihl، “Lottery Scheduling: Flexible Proportional-Share Resource Management”، OSDI 1994. اطلاعات کتاب‌شناختی را پیش از تحویل با شیوه‌نامهٔ درس تطبیق دهید.
